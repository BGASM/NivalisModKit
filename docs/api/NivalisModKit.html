DevCommands

Named commands that development tools can run in the game through the dev bridge (POST http://127.0.0.1:5710/cmd/name?arg=value, or tools/bridge.sh cmd name arg=value). For test mods and debugging: open a window, set up a situation, read back a result. Commands run on the main thread, so they can use the game and the kit freely. Running them needs the kit's [DevBridge] Enabled and AllowCommands; registering always works and costs nothing.

GameBuild

Which build of the game is running, and whether this kit was tested on it. The game's own version string stays "1.0" across patches, so the kit identifies the build by its code (a fingerprint of GameAssembly.dll).

GameClock

The game clock's speed and pausing, shareable between mods. Each mod sets its own factor under its own owner name; the kit applies the product of all factors, so two mods that each want 2x get 4x, and removing one restores the other's. Factors survive save loads. Main thread only.

GameEvents

Game events raised by the kit. Subscribe in your plugin's Load. An event whose patch failed to install never fires; check IsAvailable(string) to degrade gracefully.

ModMenu

The kit's "Mods" button in the pause menu, shared by every mod. Clicking it opens the mod browser: by default the kit's own, which lists each mod's settings and the pages mods add with AddPage(string, string, Action<KitWindow>). A mod can replace the browser with its own (SetBrowser(string, Action)). Main thread only.

ModSetting

How a setting appears in the in-game mod browser. Pass one as a tag when you bind the setting:

Config.Bind("General", "Verbose", false,
    new ConfigDescription("Log every decision.", null, new ModSetting { IsAdvanced = true }));

Listing is opt-in: a setting appears when it has this tag, or when its mod called ListSettings(string) (then all of its settings appear, and these flags adjust them). The browser also reads BepInEx ConfigurationManager's ConfigurationManagerAttributes tag to adjust listed settings, but that tag alone doesn't list a setting.

Pricing

Change vendor prices. Handlers adjust Price; the result is what the shop shows and what is actually charged or paid, for the player and for venue managers alike. Nothing is installed until a mod subscribes. Prices are recalculated on every lookup, so a handler can change its rules at any time (for example from a live-reloaded setting).

Purchasing

Manager ingredient purchasing. Once any mod subscribes to VendorOrdering or OrderQuantity, the kit takes over each recipe's purchases: it collects the vendor offers the game makes, lets handlers set the quantity and the vendor order, then buys only up to that quantity, stopping at the first failed purchase (almost always the venue out of money). With no subscribers the kit leaves purchasing to the game.

SaveData

Data that belongs to one save, stored next to it as <save>.modkit.json. Values are kept per mod and per key, as JSON. Read and set them any time during gameplay; the kit writes the file when the game saves and reads it back when that save loads. A new game starts empty.

Scheduler

Run code later, on the main thread: next frame, after some game time, at a clock hour, or after some days. Game-time schedules are checked every frame against the clock, so sleeping past the moment still runs them (once, when the clock passes it). Everything pending is cancelled when a save loads or a new game starts; keep longer plans in SaveData.

Staff

Task priority for characters, staff included. Each character (Person) points to an ActionPriorityList asset: an ordered list of the actions it considers, first = most important. Game patch 2 (October 2, 2026) set the staff order to serve, process ingredient, make meal, take order, deliver, buy, manage complaint, cleanup meal, cleanup trash, cleanup storage.

Tuning

Change game rules: crop yield and growth speed, fish yield, property prices, security awareness gain. Each is an event whose handlers adjust a value; nothing is patched until a mod subscribes to that event. Handlers run in the order added, each seeing the previous one's value; one that throws is logged and skipped. For vendor prices see Pricing.

Ui

The game's UI: which screens are open, and the game's own notifications and dialogs. Screens are UIPanel MonoBehaviours placed in the scene (prefabs), shown and hidden by the game; PanelShown and PanelHidden report them. Call these from the main thread (event handlers, Update, the Scheduler).
